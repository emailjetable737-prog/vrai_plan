October 4 to December 15, 2026

Your Java Backend Job Plan

This plan tells you exactly what to do every day, hour by hour, from tomorrow until December 15. Open the page for the current week, do the hours in order, and tick each one when it is done.

What you are looking for

You are looking for a junior or intermediate Java backend developer role. The title might be Software Developer, Backend Developer, Java Developer or Software Engineer. The role should be in Montreal or Toronto, or remote within Canada, at a company that builds its own software, such as a bank, an insurer, a national company or a startup.

You are not looking for QA, SDET or test automation roles, contact-centre or IVR work, or another consulting or staffing company.

What you will learn

  1. Java 21, your main language, refreshed with daily exercises.
  2. SQL and PostgreSQL, from zero to designing your own database.
  3. Spring Boot 3, used to build a real REST API called Order Manager, secured with Spring Security and JWT, with a Redis cache.
  4. JUnit 5 and Mockito, where your QA experience becomes a strength.
  5. Git, GitHub, Maven and GitHub Actions, the everyday developer tools.
  6. Docker and Docker Compose, to run your project anywhere.
  7. Kafka, to make your project event-driven with a second service.
  8. Kubernetes, to run and troubleshoot your project on a cluster.
  9. AWS hands-on, by deploying your project on EC2 with a budget alert to keep it safe.
  10. AWS Certified Cloud Practitioner, with the exam planned for December 6.
  11. Interview skills: about 95 new LeetCode problems in Python plus regular redos, Java and Spring interview questions, Java concurrency, system design basics, and six behavioural stories in English and French.

Everything you learn goes into one project, so by the end you have one strong thing to show employers instead of many small ones.

The rules of the plan

  1. Saturday is always a rest day. Rest is what lets you keep going for ten weeks.
  2. The minimum day. If you are sick, travelling or having a very hard day, do just one LeetCode problem and send one application. That still counts as a success, and you continue normally the next day.
  3. Never try to catch up by doubling a day. If you miss something, skip it and continue with the current day. Sunday has a catch-up hour for unfinished work.
  4. The 25-minute rule for LeetCode. Try alone for 25 minutes. If you are stuck, watch the NeetCode video, close it, and write the solution again from memory.
  5. Push to GitHub every day. Your daily green squares show employers that you code consistently.
  6. Apply before you feel ready. Hiring takes four to eight weeks, so applying from Week 2 is the only way to have a chance at December 15.
  7. Only add a skill to your resume once you have used it in your project. Every plan day tells you when.

When you get an interview

When an interview is booked, use your learning and building hours for the days before it to prepare instead:

  1. Read the job posting and write down the five main skills it asks for.
  2. Research the company: what it builds, who its customers are, and any recent news.
  3. Practise “Tell me about yourself” and three of your stories out loud.
  4. Solve three LeetCode problems from the patterns you find hardest.
  5. Prepare three questions to ask the interviewer.
  6. Within one hour after the interview, write down every question you were asked, and send a short thank-you email the same day.

If you receive an offer, bring it to me before you accept, and we will review it together.

An honest note about December 15

This plan is built so that you give yourself the best possible chance of having a job by December 15. Nobody can promise that date, because the final decision always belongs to the employer. If December 15 arrives without an offer, that is not failure. The search simply continues until March 31, 2027, with a checkpoint on January 31, and you will be in a much stronger position than you are today.
