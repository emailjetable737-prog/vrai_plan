🏆 HashMap DSA Exercises — Become a Boss

Absolutely. If your goal is to become really strong at HashMaps for DSA interviews, don't just do 5 random problems. You want to progress from “I know what a dict is” → “I automatically recognize when a HashMap is the right weapon.”

Here’s the progression I’d use for you.

🟢 Level 1 — Master the Python dict

Before LeetCode, make sure these are automatic.

Exercise 1 — Create a dictionary

Create a dictionary containing:

{
    "Alice": 25,
    "Bob": 31,
    "Charlie": 22
}

Then:

  1. Print Alice's age.
  2. Add "David": 28.
  3. Change Bob's age to 32.
  4. Check whether "Charlie" exists.
  5. Check whether "Michael" exists.
  6. Delete Alice.
  7. Print the number of people.

Exercise 2 — Count numbers

Given:

nums = [1, 2, 2, 3, 3, 3, 4, 4, 4, 4]

Produce:

{
    1: 1,
    2: 2,
    3: 3,
    4: 4
}

Constraint: use a dictionary.

Exercise 3 — Count characters

Given:

s = "banana"

Produce:

{
    "b": 1,
    "a": 3,
    "n": 2
}

Do not use collections.Counter yet.

Exercise 4 — Find the most frequent number

nums = [4, 1, 2, 4, 3, 4, 2, 1, 4]

Return:

4

Exercise 5 — First unique character

Given:

s = "leetcode"

Return:

"l"

Because l appears once and is the first character that appears only once.

Then try:

s = "loveleetcode"

Answer:

"v"

🟢 Level 2 — HashMap as a lookup table

Now you're going to learn the most important HashMap DSA pattern:

Have I seen this before?

Exercise 6 — Contains Duplicate

Given:

nums = [1, 2, 3, 1]

Return:

True

Because 1 appears twice.

Try:

nums = [1, 2, 3, 4]

Return:

False

Important: solve it with a dictionary first.

Exercise 7 — Two Sum ⭐⭐⭐

This is one of the most important HashMap problems.

Given:

nums = [2, 7, 11, 15]
target = 9

Return:

[0, 1]

Because:

2 + 7 = 9

Your goal is to understand this pattern:

needed = target - num

Then ask:

"Have I already seen needed?"

If yes → you found the answer.

Exercise 8 — Two Sum, but explain it

Don't just solve Two Sum.

After solving it, explain in your own words:

Why does the HashMap allow us to solve Two Sum in O(n) instead of O(n²)?

If you can't explain this clearly, redo the problem.

Exercise 9 — Intersection of Two Arrays

Given:

nums1 = [1, 2, 2, 1]
nums2 = [2, 2]

Return:

[2]

Then consider:

nums1 = [4, 9, 5]
nums2 = [9, 4, 9, 8, 4]

Return:

[9, 4]

Focus on using a HashMap/HashSet to quickly determine whether something exists.

🟡 Level 3 — Frequency Maps

This is where HashMaps start becoming extremely powerful.

Exercise 10 — Valid Anagram ⭐⭐⭐

Given:

s = "anagram"
t = "nagaram"

Return:

True

But:

s = "rat"
t = "car"

Return:

False

Think:

"Do both strings contain exactly the same characters with exactly the same frequencies?"

Exercise 11 — Ransom Note

Given:

ransomNote = "a"
magazine = "b"

Return:

False

But:

ransomNote = "aa"
magazine = "aab"

Return:

True

This teaches you:

frequency counting + comparing counts.

Exercise 12 — Majority Element ⭐⭐

Given:

nums = [2, 2, 1, 1, 1, 2, 2]

Return:

2

because 2 appears more than n / 2 times.

First solve it using a HashMap.

Don't worry about the optimal Boyer-Moore solution yet.

Exercise 13 — Top K Frequent Elements ⭐⭐⭐

Given:

nums = [1,1,1,2,2,3]
k = 2

Return:

[1, 2]

This is an important interview-level problem because it combines:

HashMap + frequency counting + another data structure.

🟡 Level 4 — Mapping relationships

Now you're going beyond simple counting.

Exercise 14 — Isomorphic Strings ⭐⭐⭐

Given:

egg
add

Return:

True

Because:

e → a
g → d

But:

foo
bar

Return:

False

This teaches you:

mapping one thing to another

Exercise 15 — Word Pattern

Given:

pattern = "abba"
s = "dog cat cat dog"

Return:

True

But:

pattern = "abba"
s = "dog cat cat fish"

Return:

False

This is another relationship mapping problem.

🟡 Level 5 — HashMap + grouping

Exercise 16 — Group Anagrams ⭐⭐⭐

Given:

strs = ["eat", "tea", "tan", "ate", "nat", "bat"]

Return groups equivalent to:

[
    ["eat", "tea", "ate"],
    ["tan", "nat"],
    ["bat"]
]

The key idea is:

Words that are anagrams need the same HashMap key.

This is a must-know HashMap pattern.

Exercise 17 — Group words by length

Given:

words = ["cat", "dog", "apple", "banana", "car"]

Produce:

{
    3: ["cat", "dog", "car"],
    5: ["apple"],
    6: ["banana"]
}

This is a simpler version of the same grouping pattern.

🟠 Level 6 — HashMap + prefix sums

Now you're entering serious DSA territory.

Exercise 18 — Subarray Sum Equals K ⭐⭐⭐⭐

Given:

nums = [1, 1, 1]
k = 2

Return:

2

Because the subarrays are:

[1, 1]
[1, 1]

This is one of the most important problems for learning:

Prefix Sum + HashMap

Don't rush this one.

Exercise 19 — Find the longest subarray with sum K

Example:

nums = [1, -1, 5, -2, 3]
k = 3

Find the length of the longest contiguous subarray whose sum is 3.

This teaches you another extremely useful pattern:

prefix sum + HashMap

🔴 Level 7 — Advanced HashMap patterns

Now we're getting into problems where you need to recognize the pattern yourself.

Exercise 20 — Longest Consecutive Sequence ⭐⭐⭐⭐

Given:

nums = [100, 4, 200, 1, 3, 2]

Return:

4

Because:

1, 2, 3, 4

This is a great HashSet/HashMap problem.

Exercise 21 — Longest Substring Without Repeating Characters ⭐⭐⭐⭐

Given:

"abcabcbb"

Return:

3

Because:

"abc"

is the longest substring without repeated characters.

This introduces:

HashMap + Sliding Window

Exercise 22 — Minimum Window Substring ⭐⭐⭐⭐⭐

Given:

s = "ADOBECODEBANC"
t = "ABC"

Return:

"BANC"

This is significantly harder.

It combines:

HashMap + frequency counting + sliding window

Don't worry if this one destroys you initially. That's normal.

🔴 Level 8 — Interview Boss Mode

These are the problems I'd eventually want you to be able to solve without immediately knowing that HashMap is the intended solution.

Exercise 23 — 4Sum II

Given four arrays, count how many combinations produce:

A[i] + B[j] + C[k] + D[l] = 0

This teaches:

HashMap + reducing a 4-part problem into two 2-part problems.

Exercise 24 — Longest Arithmetic Subsequence

Find the length of the longest arithmetic subsequence.

This introduces:

HashMap + dynamic programming

Exercise 25 — Copy List with Random Pointer

This is a great HashMap problem because you need to associate:

original node → copied node

This teaches a very important general pattern:

Use a HashMap to remember the relationship between an original object and its copy.

Exercise 26 — LRU Cache ⭐⭐⭐⭐⭐

This is boss-level HashMap knowledge.

You need:

HashMap + Doubly Linked List

The HashMap gives you:

key → node

The linked list gives you:

which item was used most recently

This is an excellent interview problem because it forces you to combine data structures.

🧠 The REAL HashMap skill

Here's something extremely important.

Don't memorize:

"Two Sum = HashMap."

Instead, learn to recognize why a HashMap is useful.

Question 1

Do I need to quickly know whether I've seen something before?

Think:

if x in seen:

Question 2

Do I need to count how many times something appears?

Think:

count[x] = count.get(x, 0) + 1

Question 3

Do I need to map one thing to another?

Think:

mapping[a] = b

Question 4

Do I need to group things based on some property?

Think:

groups[key].append(value)

Question 5

Do I need to remember information about something I've already encountered?

Think:

seen[x] = information

Question 6

Do I have a prefix-sum problem?

Think:

prefix sum + HashMap

Question 7

Do I have a sliding-window problem where I need to track frequencies?

Think:

sliding window + HashMap

🏆 Your HashMap curriculum

I would not do these randomly.

Do them in this order:

StageProblems
🟢 Fundamentals1–5
🟢 Lookup6–9
🟡 Frequency10–13
🟡 Mapping14–15
🟡 Grouping16–17
🟠 Prefix Sum18–19
🔴 Advanced20–22
🔴 Boss23–26

And here's the rule I'd use:

Don't look at the solution immediately.

For each problem:

  1. Read the problem.
  2. Spend 10–15 minutes thinking.
  3. Identify what information you need to remember.
  4. Ask whether a HashMap can store that information.
  5. Try writing the algorithm.
  6. Code it.
  7. Test it manually.
  8. Analyze time and space complexity.
  9. Only then look at the solution if you're stuck.
  10. After seeing the solution, close it and implement it again from memory.

That last step is huge.

🎯 Your ultimate goal

You should eventually see something like:

"Find whether two numbers add to X"

and almost instantly think:

needed = target - num

if needed in seen:
    ...

Or:

"How many times does each thing occur?"

and instantly think:

count[x] = count.get(x, 0) + 1

Or:

"Group things that have the same property"

and think:

groups[key].append(item)

That's when you've actually become good at HashMaps—not when you've memorized what a bucket or collision is.

If you can confidently solve Two Sum → Group Anagrams → Top K Frequent → Longest Substring → Subarray Sum Equals K → LRU Cache, you'll have a very strong HashMap foundation for interview DSA.
