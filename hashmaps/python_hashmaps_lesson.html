Python HashMaps: Everything You Need for DSA

A beginner-friendly A-to-Z guide to HashMaps using Python's dict.

Core idea: In Python, the built-in dictionary (dict) is the HashMap you will use for most DSA problems.

1. What problem does a HashMap solve?

A HashMap is designed to make looking up information associated with a key very fast.

"Michael" → 1234
"Sarah"   → 5678
"David"   → 9012

Instead of scanning a whole list to find Michael, a HashMap can normally locate the relevant entry in O(1) average time.

2. Keys and values

"Michael" → 1234
    ↑          ↑
   key       value

The key identifies the thing. The value is the information associated with it.

One key plus its value is an entry.

3. Python's HashMap is dict

phone_book = {
    "Michael": "1234",
    "Sarah": "5678",
    "David": "9012"
}

When a DSA problem says “use a HashMap,” your Python brain should usually think dict.

4. Creating a dictionary

d = {}

d = {
    "apple": 5,
    "banana": 3,
    "orange": 8
}

# Also valid, but less common:
d = dict()

5. Adding an entry

d["banana"] = 3

General pattern:

dictionary[key] = value

6. Getting a value

d["apple"]

This asks: “Find the value associated with the key "apple".”

7. Updating a value

d["apple"] = 10

If the key already exists, Python replaces its old value. Dictionary keys are unique.

8. Checking whether a key exists

if "apple" in d:
    print("Found it")

"apple" in d       # True
"grape" in d       # False

Important: key in d checks keys, not values.

9. Getting a value safely with .get()

d["banana"]          # KeyError if "banana" doesn't exist
d.get("banana")      # None if it doesn't exist
d.get("banana", 0)   # 0 if it doesn't exist

This is especially useful in DSA.

10. The most important pattern: counting

nums = [1, 2, 2, 3, 3, 3]

count = {}

for num in nums:
    if num in count:
        count[num] += 1
    else:
        count[num] = 1

Result:

{1: 1, 2: 2, 3: 3}

Cleaner Python version

count = {}

for num in nums:
    count[num] = count.get(num, 0) + 1

Read count.get(num, 0) as: “Give me the current count; if this key doesn't exist, give me 0.”

11. defaultdict

from collections import defaultdict

count = defaultdict(int)

for num in nums:
    count[num] += 1

defaultdict(int) gives missing keys a default value of 0. It is convenient, but learn normal dictionaries first.

12. Looping through a dictionary

Keys

for key in d:
    print(key)

Values

for value in d.values():
    print(value)

Keys and values

for key, value in d.items():
    print(key, value)

You should become very comfortable with .items().

13. Deleting an entry

del d["apple"]

value = d.pop("apple")

pop() removes the key and returns its value.

14. Number of entries

len(d)

15. What can be a dictionary key?

Keys must be hashable. Common examples include integers, strings, booleans, floats, and tuples whose contents are hashable.

d = {
    1: "one",
    "hello": 5,
    (1, 2): "point"
}

A list cannot be a key:

d = {
    [1, 2]: "hello"
}

This raises TypeError: unhashable type: 'list'. Mutable objects such as lists are unsuitable as keys because their contents can change.

16. Hashing

Python hashes a key internally to help determine where its entry belongs.

"Michael"
    ↓
hash
    ↓
internal location
    ↓
find entry
    ↓
1234

You can see a hash value with:

hash("Michael")

You do not need to calculate or memorize hash values yourself. Also, Python's hash() is not the same thing as a cryptographic hash such as SHA-256.

17. Buckets and collisions

Conceptually, a hash table has locations often called buckets. A hash helps determine where to look.

KEY ↓ hash ↓ bucket/location ↓ entry ↓ VALUE

A collision occurs when different keys end up competing for the same table location.

Michael → bucket 3
David   → bucket 3

The important point is that the dictionary still keeps the keys distinct and can retrieve the correct value by checking the key.

18. Important Python-specific detail: collision handling

Generic HashMap tutorials often teach chaining, where a bucket contains a list of colliding entries. That is one common collision strategy, but Python's CPython dict does not simply use that classic chaining model. CPython uses a sophisticated open-addressing-based implementation.

For DSA, you do not need to implement CPython's collision strategy. What you need to understand is:

  • Different keys can have collisions.
  • The dictionary handles those collisions internally.
  • The dictionary still checks the key so it can return the correct value.

19. How Python retrieves the right value

d = {
    "Michael": 1234,
    "David": 5678
}

d["David"]

Conceptually:

"David" ↓ hash("David") ↓ find candidate location ↓ compare keys ↓ "David" == "David" ✓ ↓ 5678

The hash helps locate the relevant area; key equality identifies the exact entry.

20. Why is dictionary lookup fast?

A normal list may require checking elements one by one. A dictionary normally uses hashing to jump close to the relevant entry instead of scanning everything.

List search:       O(n)
Dictionary lookup: O(1) average

21. Is it always O(1)?

No. Dictionary operations such as lookup, insertion, deletion, and membership are generally O(1) on average. In pathological collision situations, performance can degrade.

Python's implementation uses techniques to keep the table efficient, but you should remember the average-case distinction for DSA.

22. Resizing

As a dictionary grows, its internal table may need more space. It can resize and redistribute entries so the table remains efficient.

This is one reason individual operations are best described as average-case O(1), even though resizing work can occasionally be more expensive.

23. Dictionary order

Modern Python dictionaries preserve insertion order.

d = {}
d["a"] = 1
d["b"] = 2
d["c"] = 3

Iteration will produce a, then b, then c. This does not mean dictionaries are automatically sorted by key.

24. HashMap vs HashSet

Python's dictionary is used when you want:

key → value

Python's set is used when you mainly care whether an element exists and want unique elements.

seen = set()

if number in seen:
    # duplicate

seen.add(number)

For DSA, a useful rule is:

  • “How many times did I see this?” → dictionary
  • “Have I seen this?” → usually a set

25. The Two Sum pattern

nums = [2, 7, 11, 15]
target = 9

seen = {}

for i, num in enumerate(nums):
    needed = target - num

    if needed in seen:
        return [seen[needed], i]

    seen[num] = i

The dictionary stores a number and the index where it was seen:

number → index

For 7, the needed value is 9 - 7 = 2. The dictionary can quickly tell us that 2 was already seen.

26. Common DSA HashMap patterns

  • Frequency counting: number → count
  • Index lookup: number → index
  • Mapping: thing → information about thing
  • Grouping: category → list of items
  • Tracking: element → state/information

30. The seven things to know cold

  1. Python's HashMap = dict
  2. It stores key → value
  3. Keys must be hashable
  4. d[key], d[key] = value, and key in d are O(1) average
  5. Hashing allows fast lookup
  6. Collisions happen, but Python handles them internally
  7. Recognize the DSA patterns: counting, lookup, tracking, grouping, and “have I seen this?”

Final mental model

PYTHON DICT KEY VALUE │ │ ▼ ▼ "Alice" ────────────────────→ 25 "Bob" ────────────────────→ 30 "John" ────────────────────→ 42 When you write: d["Bob"] Python uses hashing internally to quickly locate the entry for "Bob", handles collisions internally, and returns: 30
For DSA: Don't get stuck on low-level implementation details. Understand what hashing means, know how Python dict works, memorize the common operations and complexities, and most importantly, learn to recognize when a problem calls for a fast key → value lookup.
